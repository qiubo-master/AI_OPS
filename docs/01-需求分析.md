# 01 需求分析

## 1. 项目背景与定位

项目面向全国工场店运营与技师作业，目标不是建设一个孤立的 AI 工具，而是把 AI 能力嵌入门店及技师作业系统。首批候选四场景：

1. 培训课件自动化生产：素材到脚本、语音/数字人及成片的辅助生产。
2. 门店现场图像质检：识别作业现场、陈列或服务动作中的合规问题。
3. 检测报价辅助：结合车辆检测结果、商品/服务与规则生成报价建议。
4. 车辆养护方案生成：结合车辆档案、里程、历史服务和养护知识生成建议。

既有智能客服项目沉淀的私有化模型、RAG、Agent 编排、FastAPI 推理服务、Java 集成、评测与灰度方法可复用；各场景专用算法、数据和业务责任仍需独立确认。

## 2. 已知事实与待验证假设

### 2.1 简历已确认事实

- 项目周期：2025.03—2026.06；角色：项目负责人。
- 四场景均进入过从需求到规模化上线的交付过程。
- 采用真实数据样本 + 模型桩完成端到端 POC 和早期业务演示。
- FastAPI 承载推理 API；Java/SpringCloud 对接门店、技师及车辆档案等业务系统。
- 模型能力从纯文本扩展到语音、图片等多模态。
- 上线采用单店/1% 灰度、可度量、可回滚的策略。

### 2.2 必须验证，不能直接当结论

- 四场景当前人工耗时、错误/漏检、转化损失和培训制作周期。
- 12 人团队构成是否为最终准确数字。
- 误报率、成片质量、转化率等具体基线和验收门槛。
- 四场景真实上线顺序、覆盖店数、调用量和个人贡献边界。
- 多模态能力的具体模型、部署形态及算法团队/本人职责分界。

## 3. 用户、任务与痛点假设

| 用户 | 核心任务 | 待验证痛点 | 期望结果 |
|---|---|---|---|
| 培训运营/讲师 | 生产并更新培训内容 | 制作周期长、重复劳动、版本难统一 | 降低制作耗时，保证事实和品牌一致性 |
| 店长/区域督导 | 检查门店作业合规 | 人工抽检覆盖低、尺度不一致 | 提升覆盖率，控制误报与申诉成本 |
| 技师/服务顾问 | 检测、解释并报价 | 信息分散、方案依赖经验 | 快速给出可解释、可编辑的报价建议 |
| 车主 | 获得可信养护建议 | 方案不透明或不一致 | 方案个性化、可解释、不过度推荐 |
| 运营管理者 | 评估投入与推广 | AI 效果难归因 | 指标可量化、版本可比较、异常可回滚 |

## 4. 四场景业务闭环

### 4.1 培训课件

素材/知识输入 → 结构化脚本 → 内容审核 → 语音/数字人成片 → 发布 → 学习与反馈数据回收。所有事实、品牌和安全内容必须经过人工审核后发布。

### 4.2 图像质检

门店图片采集 → 场景/质量预检 → 违规识别 → 置信度分级 → 人工复核/申诉 → 整改闭环 → 标注回流。低置信度不得直接处罚。

### 4.3 检测报价

检测结果与车辆信息 → 异常项识别 → 商品/服务/库存/价格查询 → 报价建议 → 技师确认 → 用户沟通/下单 → 转化与退改结果回收。AI 只辅助，最终价格以交易系统为准。

### 4.4 养护方案

车辆档案/里程/历史订单 → 规则与知识检索 → 个性化方案 → 风险与依据展示 → 人工/用户确认 → 服务闭环 → 反馈回收。安全相关建议需规则兜底和免责声明。

## 5. 功能范围

### P0：先验证共性底座与单场景闭环

- 统一推理 API、身份鉴权、请求追踪、模型/Prompt/知识版本管理。
- 基于 LangGraph 的场景路由、RAG、工具调用、人工审核和失败降级。
- 真实脱敏样本 + stub 的端到端 POC。
- 场景专属输入、输出、审核、反馈与效果埋点。
- Java 业务系统调用契约；超时、幂等、重试、限流和回滚。
- A/B 或影子评测、运营看板和审计留痕。

### P1：场景试点通过后

- 多店、多区域扩量；更多模态和业务系统接入。
- 标注/反馈闭环、主动学习和版本自动评测。
- 运营配置台、模板管理与精细化权限。

### 首期明确不做

- 四条链路同时全国全量上线。
- 无人工审核地自动发布课件、自动处罚门店或自动改价。
- 让生成式模型替代交易价格、维修安全规则或业务主数据。
- 重建门店、技师、商品、订单、车辆档案等存量系统。
- 在未确认收益和数据前承诺具体提升比例。

## 6. 非功能与治理需求

- 可用性：依赖不可用时回退规则/人工流程，核心作业不被 AI 阻断。
- 性能：按具体工作流分别定义同步响应、异步任务和峰值容量，数值待压测。
- 可追溯：输入、检索证据、模型/Prompt/知识版本、人工修改和结果全留痕。
- 安全隐私：车辆、用户、门店图片最小化使用、脱敏、分权、留存期限与删除机制。
- 内容安全：事实性、品牌、维修安全、价格和过度营销设置规则护栏。
- 可回滚：模型、Prompt、工作流和知识库独立版本化，支持灰度和一键切回。

## 7. 指标框架（目标值待评审）

| 场景 | 业务结果指标 | 质量指标 | 护栏指标 |
|---|---|---|---|
| 培训课件 | 制作周期、人均产能、学习完成率 | 事实准确率、审核通过率、成片评分 | 重大事实/品牌错误、返工率 |
| 图像质检 | 覆盖率、整改闭环率、人工节省 | Precision/Recall、分场景召回 | 误报率、申诉率、处罚错误数 |
| 检测报价 | 报价耗时、采纳率、转化辅助 | 推荐准确/完整率、解释可用率 | 错价率、退改率、投诉率 |
| 养护方案 | 方案生成耗时、采纳率、服务转化 | 适配率、知识引用正确率 | 过度推荐率、安全错误数、投诉率 |
| 共性平台 | 场景接入周期、复用率 | 可用性、P95 延迟、任务成功率 | 资损/隐私/安全事故、回滚时长 |

原则：模型指标不能单独作为上线依据，必须同时满足业务结果和护栏。

## 8. POC 方案

### 8.1 目标

用真实脱敏样本跑通“业务请求 → Agent/模型/工具 → 人工审核 → 业务系统结果 → 埋点回收”，验证价值、数据、接口和安全边界。

### 8.2 建议切片与顺序

不默认四场景并行。Gate 0 用“价值 × 可行性 × 风险 × 数据就绪度”评分后，选择 1 个主场景 POC；建议优先比较培训课件与图像质检，因闭环边界相对独立。报价和养护方案涉及实时价格、车辆安全与交易责任，应在接口与护栏成熟后进入生产试点。

### 8.3 POC 通过条件

- 痛点和价值基线有业务证据；真实样本合法可用。
- 端到端链路、人工审核、降级和埋点全部跑通。
- 场景质量不劣于人工/现行规则基线，护栏零越线或在批准阈值内。
- 业务 owner 接受新流程并确认试点范围。
- 能测算试点成本、潜在收益和工程化差距。

## 9. 需求调研清单

1. 四场景各自当前流程、频次、耗时、成本和错误基线是什么？
2. 谁是 sponsor、业务 owner、内容/安全最终签字人？
3. 哪个场景价值最大且样本、接口最就绪？
4. 各类图片、车辆和用户数据的授权、脱敏、留存要求是什么？
5. 课件发布、质检处罚、报价、养护建议分别由谁最终确认？
6. 门店/技师系统可提供哪些接口、调用量、SLA 和发布窗口？
7. 商品、库存、价格、车辆档案与知识库的权威数据源分别是什么？
8. 人工基线和对照组怎样设计，收益由谁确认？
9. 发生错价、误报、安全错误或模型不可用时如何降级与追责？
10. 智能客服基座哪些组件可直接复用，哪些需改造或隔离？
