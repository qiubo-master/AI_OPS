# AI视觉能力与门店巡检产品PRD（V0.1）

## 1. 产品定义

### 1.1 产品名称

AI视觉能力中心与门店视觉巡检。

### 1.2 产品形态

- AI运营工作台新增“AI图像质检”模块。
- 智能客服新增图片消息和视觉问答能力。
- 门店部署边缘推理设备和设备Agent。
- 督导通过工作台/企业微信接收待核查事件。

### 1.3 产品原则

- AI只生成待核查事件，不直接认定门店违规。
- 高风险客服场景不只凭图片给出确定性诊断。
- 端侧优先处理视频，只上传异常证据。
- 不做人脸识别，不识别员工身份。
- 所有模型结果必须携带模型版本、置信度和证据。

## 2. 用户与权限

| 角色 | 权限 |
|---|---|
| 总部运营 | 查看全国数据、配置规则模板、发起专项巡检 |
| 区域运营 | 查看辖区门店、统计趋势和整改情况 |
| 区域督导 | 核查告警、派发整改、复验和标记误报 |
| 门店店长 | 接收整改、上传证据、查看本店历史 |
| 客服坐席 | 在会话中查看视觉识别结果和风险提示 |
| 算法运营 | 查看误报漏报、样本入池、模型效果 |
| 系统管理员 | 管理门店、设备、摄像头、模型和权限 |

## 3. 核心流程

### 3.1 门店巡检流程

```text
摄像头采集
→ 边缘模型识别
→ 多帧规则判断
→ 生成异常事件
→ 云端去重和分派
→ 督导人工核查
→ 确认异常/误报
→ 门店整改
→ 督导复验
→ 关闭事件
→ 样本回流
```

### 3.2 智能客服视觉流程

```text
用户上传图片
→ 文件安全与图片质量检查
→ OCR/检测/VLM任务路由
→ 输出结构化视觉结果
→ RAG召回业务知识
→ DeepSeek-R1组织答案
→ 低置信度补拍/转人工/到店提示
→ 记录模型与知识引用
```

## 4. 功能需求

### 4.1 门店与设备管理

#### FR-01 门店设备台账

- 展示门店、区域、负责人、边缘设备和摄像头数量。
- 展示设备在线状态、最后心跳、温度、磁盘、版本和异常。
- 支持按区域、状态、版本筛选。

#### FR-02 摄像头接入

- 支持RTSP、USB和CSI摄像头。
- 记录摄像头名称、位置、用途、分辨率和码流。
- 支持连通性检查、预览和画面截图。
- 支持配置检测ROI、多边形区域和忽略区域。

#### FR-03 摄像头健康检测

- 识别离线、黑屏、遮挡、严重模糊和角度变化。
- 设备端缓存最近一次正常画面用于对比。

### 4.2 巡检规则管理

#### FR-04 规则模板

- 总部维护Logo、工服、灭火器和应急通道规则模板。
- 规则包含有效时间、采样周期、置信度、多帧持续时长、冷却时间和责任人。
- 门店可配置合理例外，但需保留审批记录。

#### FR-05 多帧聚合

- 单帧检测不直接产生告警。
- 应急通道等场景满足连续时长后生成事件。
- 同一摄像头、同一规则在冷却期内合并重复事件。

### 4.3 事件与告警

#### FR-06 事件生成

事件至少包含：

- 事件ID、门店、摄像头、规则和时间。
- AI标签、置信度、模型版本和边缘设备版本。
- 原始截图、带检测框截图和证据视频。
- 当前状态、负责人和处理时限。

#### FR-07 督导核查

- 支持确认异常、误报、无法判断和合并事件。
- “无法判断”可要求门店补拍或现场检查。
- 误报必须选择原因：光照、遮挡、摄像头偏移、模型误识别、规则不适用等。

#### FR-08 告警通知

- P0安全事件实时通知督导。
- 非安全类事件可按门店聚合，避免消息轰炸。
- 支持工作台通知，企业微信作为推荐外部渠道。
- 支持超时升级至区域运营。

### 4.4 整改闭环

#### FR-09 整改任务

- 确认异常后自动生成整改任务。
- 包含问题说明、整改标准、负责人和截止时间。
- 门店上传整改说明、照片或短视频。

#### FR-10 复验与关闭

- 督导通过、驳回或要求重新整改。
- 支持整改前后图片对比。
- 关闭后保留事件、核查、整改和复验全链路。

### 4.5 运营看板

#### FR-11 核心指标

- 门店合规率、事件数、确认异常数和误报率。
- 平均核查时长、平均整改时长、逾期数。
- 区域/门店排名和高频问题。
- 不同模型版本的事件准确率和无效告警数。

### 4.6 智能客服图片能力

#### FR-12 图片消息

- 支持JPG、PNG、WebP，首期单图不超过10MB。
- 支持单轮1至5张图片。
- 上传时检查文件类型、大小、图片质量和安全风险。
- 清除非必要EXIF信息。

#### FR-13 图片任务路由

- 订单、报价单、检测报告优先进入OCR和版面解析。
- 轮胎照片进入胎侧OCR、业务检测和通用视觉理解。
- 仪表盘进入图标检测和RAG解释。
- 无法分类时进入通用VLM，并限制其直接业务决策权限。

#### FR-14 客服视觉结果

- 坐席可查看图片类型、识别文字、视觉标签和置信度。
- 低质量图片提示用户重拍，包括距离、光线和角度建议。
- 高风险问题必须展示“仅凭图片无法确认”的安全提示。
- 最终回答记录视觉模型、RAG和大模型版本。

### 4.7 模型与样本管理

#### FR-15 模型版本

- 展示模型名称、任务、版本、指标、状态和适用硬件。
- 支持测试、灰度、正式、停用和回滚状态。
- 边缘设备上报实际运行模型版本。

#### FR-16 样本反馈

- 督导误报和客服人工修正进入候选样本池。
- 入训练集前必须完成授权、脱敏、去重和标注审核。
- 训练集、验证集、测试集按门店和时间隔离，防止数据泄漏。

## 6. 状态机

```text
AI已发现
→ 待督导核查
→ 确认异常 / 误报关闭 / 无法判断
→ 待门店整改
→ 待督导复验
→ 已关闭 / 驳回重改
```

事件状态变化必须记录操作者、时间、原因和证据。

## 7. 数据结构概要

### 7.1 主要实体

- Store：门店。
- EdgeDevice：边缘设备。
- Camera：摄像头。
- InspectionRule：巡检规则。
- ModelVersion：模型版本。
- DetectionEvent：AI检测事件。
- ReviewDecision：督导核查记录。
- RectificationTask：整改任务。
- EvidenceAsset：图片/视频证据。
- VisionRequest：客服视觉请求。
- FeedbackSample：误报漏报和标注样本。

### 7.2 事件幂等

- 边缘事件使用`device_id + camera_id + rule_id + event_start_time`形成幂等键。
- 重传不得生成重复事件。
- 同一问题在冷却期内更新持续时间和证据，不重复通知。

## 8. 非功能需求

### 8.1 性能

- 安全场景端侧推理与规则延迟不超过30秒。
- 工作台事件列表P95响应不超过2秒。
- 图片上传后5秒内返回处理中状态。
- 通用视觉任务支持异步执行和超时降级。

### 8.2 可用性

- 云端核心服务月可用性目标99.9%。
- 边缘断网不影响本地识别。
- 设备恢复网络后自动补传。
- 模型更新失败自动保留上一稳定版本。

### 8.3 安全与隐私

- 图片和视频使用短期签名URL访问。
- 客服图片与员工巡检图片逻辑隔离。
- 默认不做人脸识别。
- 异常证据默认保存30天，训练样本需另行授权。
- 下载、查看和标注行为记录审计日志。

## 9. 埋点与运营指标

- 视觉请求量、成功率、延迟、模型路由和转人工率。
- 门店事件数、人工确认率、误报原因和整改时长。
- 每个摄像头每日推理次数和有效事件数。
- 模型版本分布、灰度设备数和回滚次数。
- 图片质量不合格率和用户补拍成功率。

## 10. MVP验收用例

1. 断网30分钟期间门店产生应急通道事件，联网后事件只补传一次。
2. 应急通道短暂经过人员不告警，持续堆物达到阈值后告警。
3. 督导确认异常后，门店收到整改任务并上传整改照片。
4. 督导复验通过后事件关闭，所有操作可追溯。
5. 用户上传轮胎胎侧照片，系统提取规格并结合RAG解释。
6. 用户上传模糊图片，系统提示补拍而不是输出确定结论。
7. 模型灰度失败时，边缘设备恢复上一稳定版本。

## 11. 待评审决策

- 试点门店和摄像头清单。
- 企业微信通知是否纳入MVP。
- 图片/视频保存期限。
- 智能客服图片是否允许进入训练候选池。
- 工服标准和门头规则的业务定义。
- P0场景最终准确率与误报容忍度。
