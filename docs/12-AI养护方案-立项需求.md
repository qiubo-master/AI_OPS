# AI车辆养护方案项目立项需求（V0.1）

## 1. 项目定义

AI车辆养护方案是基于车辆档案、车型年款、当前里程、使用年限、历史订单、检测结果、厂家周期、业务知识和车主使用场景，生成阶段性、可解释、不过度推荐的车辆养护建议，并由服务顾问或车主确认后进入预约、检测或报价流程。

养护方案回答的是“这辆车在当前及未来一段时间应该关注什么、为什么、何时检查或处理”，不负责生成权威商品价格。需要成交的项目跳转AI检测报价或现有交易系统完成实时适配、库存和价格试算。

## 2. 立项背景

### 2.1 当前问题

- 车辆档案、里程、历史订单、检测结果和厂家保养规则分散。
- 服务建议依赖人员经验，口径不一致。
- 车主难以区分安全必检、周期保养和可延后观察项目。
- 历史已完成项目未被有效识别，可能产生重复推荐。
- 方案缺少依据和解释时，容易被用户认为是过度营销。
- 方案效果缺少后续检测、采纳、投诉和车辆状态回流。

### 2.2 建设机会

现有智能客服大模型、RAG、视觉服务、检测报价以及车辆/订单数据可作为公共底座。通过“确定性规则＋知识检索＋大模型解释”组合，可生成比纯规则更易理解、比纯大模型更安全的个性化养护方案。

## 3. 项目目标

### 3.1 业务目标

- 缩短服务顾问制定和解释养护方案的时间。
- 提升不同门店和人员的建议一致性。
- 减少重复、冲突和无依据的服务推荐。
- 让车主理解建议依据、优先级和可延后条件。
- 建立从方案、预约、检测、报价、服务到反馈的闭环。

### 3.2 技术目标

- 建立统一车辆画像与车辆时间线。
- 将厂家周期、业务规则、安全规则和历史服务做确定性计算。
- 通过RAG提供可引用的养护知识和解释依据。
- 使用DeepSeek-R1将结构化建议组织成不同角色可读的方案。
- 对方案版本、数据快照、规则、知识和人工修改全程留痕。

### 3.3 非目标

- 不替代专业检测和维修诊断。
- 不依据车龄或里程直接断言某部件已经损坏。
- 不自动下单、自动收费或承诺故障一定解决。
- 不重建车辆主数据、订单、会员和交易系统。
- 不将提升客单价设为唯一目标。
- 不向用户隐藏建议依据、风险和不确定性。

## 4. 方案输入

- VIN解析的品牌、车型、年款、动力类型、配置和适配信息。
- 当前里程、上牌时间、地区和季节。
- 历史保养、维修、检测和商品订单。
- 最近一次检测异常和技师确认结果。
- 车主自述使用场景：城市通勤、长途、高速、低温、高温、多尘等。
- 厂家手册周期、公司养护知识、服务规范和安全规则。
- 新能源车辆的动力类型和专属检查项。

## 5. 方案输出

- 当前必须检查的安全项。
- 当前建议处理的周期项目。
- 可延后观察的项目和触发条件。
- 未来1个月/3个月/6个月的时间线。
- 每项建议的依据、最近服务记录和风险说明。
- 需要补充的信息或到店检测项。
- 面向服务顾问的专业版和面向车主的易懂版。
- 可选择项目，确认后进入检测报价。

## 6. 首期场景

### P0

1. 燃油车常规保养方案：机油、机滤、空气滤芯、空调滤芯、轮胎、电瓶等。
2. 轮胎周期与状态养护：里程、年限、换位、胎压和检测异常。
3. 电瓶检查与更换提醒：历史检测、使用年限和低温场景。
4. 基于历史订单去重和近期已服务项目抑制。

### P1

- 新能源车辆专属养护。
- 季节性和长途出行检查包。
- 多车家庭和企业车队方案。
- 与智能客服对话联动生成方案。

涉及制动、转向、发动机、动力电池等高风险领域时，首期只生成检查建议，必须以专业检测结果为准。

## 7. 核心流程

```text
选择车辆/用户授权
→ 汇总车辆档案和历史时间线
→ 校验里程与数据时效
→ 规则引擎生成候选建议和禁忌项
→ RAG检索厂家/业务依据
→ AI生成个性化方案与解释
→ 服务顾问审核或用户确认
→ 选择到店检查/进入检测报价
→ 回收检测、订单和反馈结果
```

## 8. 指标体系

### 8.1 业务指标

- 方案生成耗时。
- 方案查看、咨询、预约和到店率。
- 建议采纳率和进入检测报价率。
- 服务顾问使用率和人工编辑耗时。

### 8.2 质量指标

- 车辆画像完整率。
- 历史项目去重准确率。
- 建议适配率。
- 知识引用正确率和可解释性评分。
- 人工审核通过率和平均修改项数。

### 8.3 护栏指标

- 严重安全错误数为0。
- 明显重复推荐率低于评审阈值。
- 无依据项目进入确认方案数为0。
- 过度推荐率、投诉率和退改率不高于对照组。
- 数据过期或缺失时生成确定性处理结论数为0。

## 9. POC设计

- 试点门店：建议5至10家。
- 首期车型：选择数据质量较高、保有量较大的燃油车型。
- 样本：至少3000条脱敏车辆时间线，覆盖不同车龄、里程和历史服务情况。
- 运行方式：先离线回放，再由服务顾问影子评审，不直接向客户发送。
- 评估：与现有人工方案/规则方案比较完整性、重复率、审核修改和解释质量。

## 10. 依赖条件

- 车辆档案和VIN解析。
- 可信的当前里程及更新时间。
- 历史订单、检测和服务记录。
- 厂家周期和公司养护知识。
- 已确认检测异常。
- 用户授权和隐私规则。
- 检测报价/预约/智能客服接口。

## 11. 资源与费用初估

| 类别 | 初步估算 |
|---|---:|
| 车辆时间线与历史数据治理 | 5万至12万元 |
| 厂家周期与养护知识治理 | 5万至15万元 |
| 规则、RAG和方案服务研发 | 18万至40万元 |
| 前端、接口、测试和评测 | 10万至25万元 |
| POC总投入 | 38万至92万元 |

主要成本不确定性来自厂家数据授权、历史订单质量、里程时效和车型覆盖范围。

## 12. 风险与控制

| 风险 | 控制措施 |
|---|---|
| 里程不准确 | 展示数据时间；允许用户/门店确认；过期则降级 |
| 历史订单缺失 | 明确“基于当前可见记录”；要求到店核查 |
| 重复推荐 | 历史时间线硬去重；服务完成后的冷却窗口 |
| 过度推荐 | 必检/建议/观察分级；人工审核；投诉回流 |
| 厂家规则冲突 | 厂家规则优先级和版本治理；冲突转人工 |
| 新能源规则误用 | 动力类型硬路由；不同知识域隔离 |
| 大模型夸大风险 | 结构化事实输入；禁用绝对化话术；安全模板 |

## 13. 里程碑

| 阶段 | 周期 | 交付 |
|---|---:|---|
| 数据和规则审计 | 3周 | 车辆画像、历史质量、知识授权和优先车型 |
| 离线方案POC | 4至6周 | 规则/RAG/方案原型和黄金集评估 |
| 顾问影子评审 | 3至4周 | 人工修改、重复率和解释反馈 |
| 5至10店灰度 | 4至6周 | 真实用户确认、预约和报价联动 |
| 规模化评审 | 2周 | 价值、质量、投诉和成本报告 |

## 14. Gate 0待确认

1. 车辆档案和里程的权威来源。
2. 厂家保养周期数据的授权、版本和维护责任。
3. 首期燃油/新能源范围及车型白名单。
4. 历史订单和外部保养记录缺失的处理口径。
5. 方案发送渠道和人工审核责任人。
6. 过度推荐、重复推荐和安全错误的停止线。

## 15. 立项建议

建议Conditional Go：先完成车辆时间线、知识授权和离线评测；在历史去重、安全规则、人工审核和检测报价衔接验证完成前，不直接面向用户自动推送个性化养护方案。
