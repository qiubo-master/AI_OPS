# AI视觉能力与门店巡检项目立项需求（V0.2）

## 1. 项目概述

### 1.1 项目名称

企业视觉智能底座与AI门店视觉合规巡检项目。

### 1.2 项目定位

在既有DeepSeek-R1、全业务RAG知识库和智能客服模型网关基础上，新增企业级视觉能力中心，并形成两个首批业务出口：

1. 智能客服视觉问答：支持用户上传轮胎、车辆部件、仪表盘、订单、报价单和检测报告等图片，由视觉服务完成识别，再交由DeepSeek-R1结合RAG生成业务回答。
2. AI门店视觉巡检：采用“云端训练与运营、门店边缘推理”的方式，对Logo/门头、工服、灭火器、应急通道等合规要求进行持续巡检，异常进入督导核查和门店整改闭环。

本项目不重新训练或替换DeepSeek-R1。DeepSeek-R1继续负责文本推理和答案组织，新增视觉模型负责图片理解和结构化识别。

## 2. 立项背景

### 2.1 现状

- 第一版智能客服仅支持文本，不支持图片上传、OCR、图像理解和视觉业务判断。
- 门店合规检查以人工巡店和抽查为主，覆盖频率、判断口径和整改跟踪存在差异。
- 客服、门店巡检、检测报告等场景可能重复建设图片上传、模型接入、数据标注、对象存储和审计能力。
- 门店网络质量不稳定，全天视频不适合全部上传云端分析。

### 2.2 核心问题

- 客服无法直接理解用户提供的图片证据，增加追问和转人工成本。
- 督导需要耗费大量时间寻找门店问题，而不是核实和推动整改。
- 缺乏统一的视觉数据、模型版本、效果评估和反馈闭环。
- 单纯使用云端视觉大模型分析门店视频，会产生不可接受的网络、时延和推理成本。

## 3. 项目目标

### 3.1 业务目标

- 建立可被多个业务系统复用的企业视觉能力API。
- 让智能客服支持“图片识别＋业务知识＋文本推理”的多模态问答。
- 实现门店视觉异常从发现、告警、核查、整改到复验的闭环。
- 将督导工作从“人工寻找问题”转为“核查AI事件并推动整改”。
- 沉淀可持续迭代的途虎视觉数据集、模型和评估体系。

### 3.2 技术目标

- 云端建设视觉网关、OCR、通用视觉理解、业务检测、模型注册和数据反馈能力。
- 门店端支持RTSP/USB/CSI视频接入、本地推理、规则聚合、断网缓存和模型更新。
- 云端模型可导出ONNX，并转换为TensorRT FP16/INT8端侧模型。
- 视觉服务与现有模型网关、RAG、鉴权、审计和监控体系集成。

### 3.3 首期非目标

- 不做人脸识别、员工身份识别或基于人脸的绩效分析。
- 不承诺通过普通远景摄像头识别灭火器压力表数值、工服细微污渍或Logo轻微色差。
- 不上传或长期保存门店24小时完整视频。
- 不由AI直接认定门店违规；AI生成待核查事件，最终结论由督导确认。
- 不从零设计新的基础视觉网络结构。

## 4. 首期业务范围

### 4.1 智能客服视觉场景

| 优先级 | 场景 | 首期能力 |
|---|---|---|
| P0 | 轮胎胎侧照片 | OCR识别规格、品牌和可见文字；结合RAG解释规格 |
| P0 | 轮胎外观照片 | 识别明显鼓包、裂纹、扎钉等疑似问题，低置信度提示补拍或到店检查 |
| P0 | 订单/报价单/检测报告 | OCR和版面解析，提取关键字段并结合业务规则答疑 |
| P1 | 仪表盘图片 | 识别常见指示灯并给出知识解释，不替代专业诊断 |
| P1 | 车辆部件照片 | 通用视觉理解、部件分类和补充信息询问 |

### 4.2 门店巡检场景

| 优先级 | 场景 | 首期判断 |
|---|---|---|
| P0 | Logo与门头 | 缺失、遮挡、明显损坏、营业时段未亮 |
| P0 | 工服穿戴 | 指定作业区域人员是否穿着标准工服 |
| P0 | 灭火器 | 指定位置是否缺失、移位或被遮挡 |
| P0 | 应急通道 | 指定区域是否被车辆、纸箱或杂物持续占用 |
| P1 | 摄像头健康 | 离线、黑屏、遮挡、严重模糊和角度变化 |

### 4.3 “24小时监控”定义

- 设备和摄像头服务24小时在线。
- 安全通道、灭火器遮挡等场景按1至5秒采样分析。
- 工服场景在检测到人员进入指定ROI后触发。
- Logo和门头按营业前、营业中、闭店前定时巡检。
- 默认只上传异常截图及异常前后10至20秒视频。
- 断网期间继续本地推理，网络恢复后补传未同步事件。

## 5. 项目价值

### 5.1 直接价值

- 提升客服一次解决率，降低纯图片问题的人工转接。
- 提高门店巡检覆盖频率和问题发现及时性。
- 缩短异常发现到整改的时间。
- 统一全国门店巡检标准和证据格式。

### 5.2 平台价值

- 建成企业共享视觉底座，后续可复用到检测报价、维修诊断、供应链质检等业务。
- 沉淀业务视觉数据、标注规范和模型资产。
- 统一图片安全、脱敏、存储、审计和模型治理。

## 6. 建议试点

- 试点门店：默认5家，覆盖不同区域、门店面积、光照和网络条件。
- 单店摄像头：默认4路，优先复用支持RTSP的现有摄像头。
- 边缘设备：POC使用Jetson Orin Nano Super；规模试点改用工业级Orin Nano或Orin NX整机。
- 试点场景：4个P0巡检场景＋3个P0客服视觉场景。
- 观察期：前2周只生成事件，不直接纳入门店考核。

## 7. 验收指标

### 7.1 门店巡检

- 事件召回率不低于90%。
- 人工确认后的事件准确率不低于85%，试点结束目标90%。
- 单店日均无效告警不高于2条。
- 安全类异常从满足持续条件到生成事件不超过30秒。
- 弱网事件补传成功率不低于99%。
- 边缘设备在线率不低于99%。
- 督导核查闭环率不低于95%。

### 7.2 智能客服视觉

- 支持图片上传、多图会话和图片质量提示。
- P0文档类关键字段提取准确率达到评审阈值。
- 胎侧规格识别按字段统计准确率，而非只统计整图成功率。
- 高风险图片回答必须包含人工/到店确认提示。
- 每次回答可追溯视觉模型、RAG知识和大模型版本。

### 7.3 平台能力

- 统一视觉API服务智能客服和门店巡检两个业务。
- 模型支持版本发布、灰度、回滚和设备状态追踪。
- 图片、事件和人工反馈形成可审计的数据链路。

## 10. 风险

- 摄像头角度和画质不满足算法要求。
- 不同门店工服、门头、光照和遮挡差异导致模型域偏移。
- 告警过多导致督导疲劳。
- 将单帧模型准确率误当作业务事件准确率。
- 员工和用户图片缺少授权、脱敏和删除机制。
- 开发套件直接用于批量生产，稳定性和供货不可控。
- 客服将视觉结果表述为确定性安全诊断。

## 11. 途虎门店现网摄像设备调查与项目选型

### 11.1 调查口径与结论

- 调查基准日：2025年12月31日；公开资料复核日：2026年8月12日。
- 可以确认的事实：途虎官方隐私说明明确提到门店直播功能会通过摄像头采集人员影像和车辆信息；公开报道显示途虎工场店服务工位安装摄像头，用户可以在客户端查看施工过程；2025年公开报道还提到门店整洁度、操作合规等场景已使用AI视频识别。
- 不能确认的事实：截至本次调查，途虎官网、港交所年报/中报、隐私政策、公开采购及主流媒体报道均未披露全国门店统一使用的摄像头品牌、IPC型号、NVR型号或边缘计算盒型号。
- 因此，不能把海康威视、大华或某个具体SKU写成“途虎截至2025年底真实在用型号”。途虎门店包含不同建设年份和经营主体，现网设备很可能存在多品牌、多型号并存；最终型号必须以现场铭牌、NVR设备清单或采购BOM为准。

主要公开证据：

1. [途虎养车第三方信息共享清单/隐私说明](https://m.tuhu.cn/static/app/safeAccount/privacyList.html)：说明门店直播功能通过摄像头采集个人影像、车辆信息。
2. [途虎养车隐私政策（2025-06-30版）](https://m.tuhu.cn/user/privacy/privacy250630.html)：说明进入监控区域的人员影像及车辆信息可能被采集并用于门店直播展示。
3. [文汇报：途虎工场店数字化服务报道](https://whb-oss.oss-cn-shanghai.aliyuncs.com/zhuzhan/kjwz/20230704/526294.html)：报道服务工位安装摄像头，消费者可在手机端查看施工过程。
4. [人民网：途虎“无接触服务”报道](https://auto.people.com.cn/n1/2020/0217/c1005-31591182.html)：将门店摄像头开启列为服务过程要求之一。
5. [新浪财经：途虎门店AI视频识别应用报道](https://cj.sina.com.cn/articles/view/1887344341/707e96d502001o29u)：提到使用AI视频识别辅助门店整洁、操作合规等运营检查。该项属于媒体报道，不等同于设备型号披露。

### 11.2 Gate 0现网核验方法

在采购新摄像头前，先对5家试点门店完成设备盘点，输出《现网摄像头兼容性清单》。每家门店至少执行以下检查：

1. 拍摄IPC、NVR、PoE交换机和边缘主机铭牌，记录品牌、完整型号、序列号后四位、固件版本和安装年份。
2. 从NVR导出通道表，记录各通道分辨率、帧率、编码、码率、IP地址、在线状态和录像保存天数。
3. 通过ONVIF Device Information、厂商接口或设备管理页读取型号，验证RTSP主/子码流，不以肉眼外观猜型号。
4. 连续拉流72小时，检查断流率、时间同步、夜间画质、逆光、遮挡和画面抖动。
5. 按Logo、工服、灭火器、应急通道四类任务检查机位和目标像素；不满足算法条件时优先调整机位或镜头，再决定换机。
6. 清理默认密码，使用设备级独立账号，并确认固件升级、日志审计和摄像网络隔离能力。

### 11.3 现有摄像头复用准入线

现网摄像头满足下列条件时原则上保留，不因品牌不同而整批更换：

| 项目 | POC最低要求 | 推荐要求 |
|---|---|---|
| 接入协议 | 可稳定输出RTSP | RTSP＋ONVIF，或支持GB/T 28181 |
| 分辨率 | 1920×1080 | 4MP及以上；门头远景优先8MP |
| 帧率 | 15 fps | 20/25 fps，支持主/子双码流 |
| 编码 | H.264 | H.265/H.264可配置 |
| 供电 | 稳定供电 | PoE 802.3af/at |
| 动态范围 | 室内目标可辨 | 门头、出入口不低于120 dB WDR |
| 运维安全 | 可修改密码、可校时 | 独立账号、固件可升级、日志可查、摄像网隔离 |
| 稳定性 | 72小时测试无持续断流 | 月在线率不低于99% |

### 11.4 摄像头推荐选型

本项目推荐“标准网络摄像头＋统一边缘计算盒”，不把摄像头内置AI作为主推理平台。这样可兼容途虎现有异构摄像头，模型只在边缘盒维护一次，也便于后续把视觉能力复用给智能客服。

| 点位/任务 | 推荐规格 | 候选设备或产品族 | 选型结论 |
|---|---|---|---|
| 维修工位、工服、灭火器 | 4MP，2.8 mm广角或2.7—13.5 mm电动变焦，25 fps，120 dB WDR，PoE，RTSP/ONVIF | [海康威视DS-2CD5A47EFWD系列](https://www.hikvision.com/cn/products/pdplist/45085/)；[大华400万易智能红外变焦半球系列](https://www.dahuatech.com/product/info/13014.html) | 优先复用现网；新增时首选4MP电动变焦半球/筒机，安装后可远程校准取景 |
| 门头Logo、室外远景 | 8MP，电动变焦，120 dB WDR，低照度补光，PoE，IP66/67 | [海康威视DS-2CD2T86FWDV3-ZAK](https://www.hikvision.com/cn/products/Exclusive-Products/products/Security/15/) | 仅在现网门头画面像素不足或逆光严重时新增；8MP用于保留Logo细节，不要求全店统一替换 |
| 应急通道 | 4MP，2.8 mm广角，WDR，PoE，IP66/67 | 海康/大华同等级4MP开放协议半球或筒机 | 以完整覆盖通道ROI为第一优先，固定广角通常比高倍变焦更合适 |
| 低预算补点 | 4MP，PoE，H.265，RTSP/ONVIF | [海康威视DS-IPC-T14HV3-LA(/POE)](https://dealer-static.hikvision.com/upload/file/doc/DOC000090219-DS-IPC-T14HV3-LA%28_POE%29.pdf) | 可用于光照稳定、距离较近的室内点位；不能替代强逆光门头的高WDR变焦机型 |

说明：表中海康威视和大华型号是本项目候选设备，不是已查实的途虎现网型号。最终采购SKU需结合焦距、补光距离、拾音需求、室内外防护、供货周期和三家询价确定。

### 11.5 边缘计算设备选型

| 阶段 | 推荐设备 | 适用范围 | 结论 |
|---|---|---|---|
| 算法开发/单店POC | [NVIDIA Jetson Orin Nano Super Developer Kit](https://docs.nvidia.com/jetson/orin-nano-devkit/user-guide/index.html) | 2—4路视频按任务采样推理；验证DeepStream、TensorRT和规则引擎 | 67 INT8 TOPS、8GB、7—25W，成本低且生态完整；仅用于开发和POC，不直接批量铺设 |
| 规模试点 | 工业级Jetson Orin Nano 8GB整机，256GB以上NVMe，双千兆网口，看门狗，宽温电源 | 单店2—4路、模型较轻、按1—5秒采样 | 作为默认量产档，必须由整机厂提供3年供货、远程恢复和质保承诺 |
| 高负载门店 | 工业级Jetson Orin NX 16GB整机 | 4—8路、较高帧率、多模型并行或后续扩展 | 在实测Orin Nano GPU/内存持续超过70%时升级，不在POC阶段超配 |

视频接入和推理管线采用[NVIDIA DeepStream](https://docs.nvidia.com/metropolis/deepstream/dev-guide/text/DS_Overview.html)＋TensorRT，统一接入RTSP流。摄像头自身的人形检测、越界检测等能力可作为降级或唤醒信号，但不得成为自研模型发布、评估和版本管理的唯一载体。

### 11.6 首批5店建议BOM与决策

1. 每店配置1台Orin Nano Super开发套件用于POC；通过验收后更换为工业级Orin Nano 8GB整机。
2. 每店先接入4路现有摄像头；通过72小时拉流和画质测试的设备全部复用。
3. 每店预留最多2个补点：门头画质不足时增加1台8MP电动变焦室外机，应急通道无完整视野时增加1台4MP广角PoE机。
4. 工位工服与灭火器检测优先共用现有工位摄像头；若目标在画面中过小、经常遮挡或机位变化，再增加4MP电动变焦机。
5. POC不采购摄像头厂商的封闭AI平台授权；模型训练、量化、灰度、回滚和事件规则均由企业视觉底座统一管理。
6. 采购预算继续沿用第9.2节的项目估算，正式下单前按“复用率、补点数量、工业整机档位、施工难度”重新询价。

最终选型结论：**现网摄像头兼容优先，新增摄像头采用4MP/8MP开放协议PoE机型，推理集中在工业级Jetson边缘盒；POC首选Orin Nano Super，规模部署默认工业级Orin Nano 8GB，高负载门店再升级Orin NX 16GB。**

## 12. Gate 0待确认事项

1. 单店接入摄像头数量及RTSP复用比例。
2. 首批试点门店名单和区域分布。
3. 工服检测细化到何种程度。
4. Logo/门头是否包含灯牌亮灭判断。
5. 告警渠道采用工作台、企业微信或两者并行。
6. 异常证据保存期限，建议默认30天。
7. 用户与员工图片训练授权机制。
8. 智能客服首期三类图片的最终优先级。
9. 5家试点门店现场盘点得到的真实IPC/NVR品牌、型号、固件和RTSP兼容率。
10. 摄像头是否由总部统一采购，或由加盟商、施工商按不同时期分别采购。

## 13. 立项建议

建议结论为Conditional Go：批准5店POC和共享视觉底座建设，不批准立即全国规模化铺设。达到事件准确率、无效告警、设备在线率、隐私合规和整改闭环指标后，再进入规模化评审。
